# Semester 1 Foundation v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish a production-quality, testable, accessible React + TypeScript + Vite foundation with GitHub Pages deployment across all eight `Inmersion-CS` Semester 1 repositories.

**Architecture:** Each repository stays independent and receives the same engineering baseline but subject-specific copy, metadata, repository base path, and README. `Calculus` is the reference implementation; after its checks pass, the same baseline is applied to `Java`, `Architecture`, `InfoSystems`, `Management`, `Japan`, `English`, and `Safety` without introducing shared runtime dependencies or a monorepo.

**Tech Stack:** React, TypeScript, Vite, npm, React Router, Vitest, React Testing Library, ESLint, Prettier, GitHub Actions, GitHub Pages.

## Global Constraints

- Repositories remain public under `Inmersion-CS` with default branch `main`.
- Implementation work happens on `foundation-v0.1` branches and reaches `main` only through verified pull requests.
- TypeScript strict mode is required.
- Dependency set remains deliberately small.
- GitHub Pages project-site base must be `/<RepositoryName>/`.
- CI must run `typecheck`, `lint`, `test`, and `build` for pushes and pull requests.
- Deployment must use the official GitHub Pages Actions flow and deploy only from `main`.
- No course-specific engines are implemented in this phase.
- No repository outside `Inmersion-CS` is modified.
- Existing MIT licenses remain unchanged.
- README text must never claim roadmap features are already implemented.

## File map used in every repository

- `package.json` — scripts and dependencies.
- `package-lock.json` — reproducible npm dependency graph; generated by npm before final merge.
- `tsconfig.json`, `tsconfig.app.json`, `tsconfig.node.json` — strict TypeScript configuration.
- `vite.config.ts` — React plugin, repository-specific base path, Vitest jsdom configuration.
- `eslint.config.js` — lint rules for TypeScript and React.
- `.prettierrc.json`, `.prettierignore` — formatting baseline.
- `index.html` — subject-specific metadata and app mount point.
- `src/main.tsx` — application bootstrap.
- `src/app/App.tsx` — router and application shell.
- `src/app/siteConfig.ts` — subject-specific identity, purpose, roadmap preview, repository URL, and base path.
- `src/app/App.test.tsx` — behavior tests for identity, navigation, purpose, and not-found route.
- `src/test/setup.ts` — Testing Library DOM assertions.
- `src/styles/global.css` — responsive, accessible foundation styling.
- `.github/workflows/ci.yml` — verification workflow.
- `.github/workflows/pages.yml` — GitHub Pages build/deploy workflow.
- `.github/dependabot.yml` — npm and Actions dependency update checks.
- `.github/ISSUE_TEMPLATE/bug_report.yml` — structured bug reports.
- `.github/ISSUE_TEMPLATE/feature_request.yml` — structured feature requests.
- `.github/PULL_REQUEST_TEMPLATE.md` — verification checklist.
- `CONTRIBUTING.md` — local setup and contribution workflow.
- `CODE_OF_CONDUCT.md` — contributor conduct expectations.
- `SECURITY.md` — responsible vulnerability reporting guidance.
- `README.md` — subject-specific public project documentation.
